# HW4 Detailed Explanation

## 1. What this homework is doing

This project builds a local HTTPS setup for a Flask app:
- Flask serves traffic on `https://localhost:5000`.
- A self-signed certificate is generated locally.
- You can add/remove that certificate from your OS trust store.
- Docker runs the app in the same way as previous homework structure.

## 2. Flask server flow

File: `main.py`

- `create_app()` creates the Flask app and defines `/`.
- `/` returns a small JSON payload, useful for quick health checks.
- `build_ssl_context(cert_path, key_path)` validates that certificate and key files exist.
- In `__main__`, Flask starts with:
  - host `0.0.0.0`
  - port `5000`
  - `ssl_context=(cert, key)`

`ssl_context` is the key part that enables HTTPS instead of plain HTTP.

## 3. Docker flow

Files: `Dockerfile`, `docker-compose.yml`

- `Dockerfile` installs Python dependencies and runs `python main.py`.
- `docker-compose.yml`:
  - builds the image
  - exposes port `5000`
  - mounts `./certs` into `/app/certs` as read-only
  - sets env vars `SSL_CERT_FILE` and `SSL_KEY_FILE` so Flask knows which files to use

Because cert files are mounted from host -> container, you generate them once locally and the container reads them.

## 4. SSL certificate + key

Generated by:
- Linux: `scripts/linux/generate_cert.sh`
- Windows: `scripts/windows/generate_cert_windows.ps1`

Output files:
- `certs/localhost.crt`: public certificate sent to clients (browser/curl)
- `certs/localhost.key`: private key used by server (must stay private)

The certificate includes SAN values:
- `DNS:localhost`
- `IP:127.0.0.1`

SAN is required by modern TLS clients for hostname verification.

## 5. Trust store scripts

Trust scripts:
- Linux: `scripts/linux/trust_cert_linux.sh`
- Windows: `scripts/windows/trust_cert_windows.ps1`

Untrust (remove) scripts:
- Linux: `scripts/linux/untrust_cert_linux.sh`
- Windows: `scripts/windows/untrust_cert_windows.ps1`

Purpose:
- Without trust-store import, browsers warn because cert is self-signed.
- With trust-store import, browser treats it as trusted for local testing.
- Untrust scripts reverse that change.

Linux note:
- The Linux script trusts in two places:
  - system CA store (`update-ca-certificates`)
  - NSS database (`~/.pki/nssdb`) via `certutil` (Chromium/Brave family)
- This helps Chromium/Brave-based browsers that rely on NSS trust data.

## 6. Python tests

File: `tests/test_hw4_ssl.py`

The tests verify application logic:

1. Home route test:
- Calls `/`
- Expects HTTP 200
- Expects expected JSON message

2. SSL context success test:
- Creates temp cert/key files
- Calls `build_ssl_context(...)`
- Expects returned file paths

3. SSL context failure test:
- Uses missing file paths
- Expects `FileNotFoundError`

These tests validate app behavior and SSL path validation logic.  
They do not validate OS trust-store behavior (that is handled by scripts + manual browser check).
